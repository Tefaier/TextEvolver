## What this is

TextEvolver is a Python 3.12 FastAPI/Jinja application that rewrites DOCX,
EPUB, HTML, and FB2 documents. Users create settings for unit conversions,
phrase replacement, image insertion, and optional Pokémon support, then submit
documents and download a ZIP produced by a separate worker.

## Commands

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/uvicorn text_evolver.main:app --reload
.venv/bin/python -m text_evolver.worker
.venv/bin/pytest
.venv/bin/ruff check src tests
```

```bash

./migrations/generate_models.sh
podman build -t text-evolver:local .
podman compose up --build
```

## Source layout

- `src/text_evolver/main.py` creates the FastAPI application, session
  middleware, templates, and static mount.
- `src/text_evolver/web/` owns HTTP routes, database-backed sessions, CSRF, flash
  messages, gettext localization, Argon2id passwords, Google OIDC, and WebAuthn.
- `src/text_evolver/web/routers/` groups health, accounts, settings/search,
  processing, Google, and WebAuthn routes. `base.py` contains only the default
  login-page GET handler, shared by `/` and `/login`.
- `src/text_evolver/web/routines/` contains router helpers grouped into rendering,
  responses, flash messages, processing status, account checks, password helpers,
  Google OIDC, and passkey encoding.
  Routers import routines; routines must not import routers.
- `web/routines/validation_utils.py` owns fixed validation rules for submitted
  values. Keep request parsing, database lookups, and authorization in callers.
- `src/text_evolver/web/interceptors/` owns access-log filters;
  `web/middlewares/` owns ASGI middleware, session state, and request locale;
  `web/utils.py` provides shared UTC time and token-digest helpers.
- `src/text_evolver/api/` owns versioned Bearer-token API routes, schemas,
  authentication, and its database middleware. The browser and API are separately
  mounted applications; only browser routes use cookie sessions, CSRF, and locale.
- `src/text_evolver/services.py` owns setting forms, upload staging, and job state
  behavior. `setting_service.py` owns shared setting persistence/authorization;
  `task_service.py` owns shared consuming ZIP downloads; `transactions.py`
  coordinates commits, staged job cleanup, and durable S3 deletion.
- `src/text_evolver/db/models.py` is generated by `sqlacodegen`. Never add
  application behavior or manual fixes to it.
- `src/text_evolver/processing/` contains the format-specific rewriting and
  headless image/Selenium integrations.
- `src/text_evolver/processing/documents/` owns stateful DOCX, EPUB, FB2, and
  HTML traversal, native-part write-back, image insertion, and atomic saving.
- `src/text_evolver/worker.py` runs a configurable thread pool; each slot
  transactionally claims a queued job and supervises its own processing child.
- `migrations/sql/{postgresql,sqlite}/` contains matching Flyway migrations.

## Runtime architecture

Compose runs PostgreSQL, PgBouncer, Flyway, MinIO, FastAPI, and one worker. The API and
worker use psycopg through PgBouncer transaction pooling; Flyway connects
directly to PostgreSQL. SQLAlchemy uses `NullPool` and disables psycopg prepared
statements because PgBouncer owns pooling.

User-provided setting images are S3 objects accessed through `boto3`. Only the
dedicated MinIO container mounts `user-data` at `/data`; app and worker use the
S3 API. PostgreSQL stores ordered object keys and byte sizes, not Base64 image
payloads. Copies own independent objects. Delete superseded objects only after
the database commit and delete newly created objects after rollback.

The API saves uploads under `WORK_ROOT/<job_id>/origin_files` and inserts a
`processing_job` row. Each of the worker's `WORKER_CONCURRENCY` thread-pool
slots atomically claims a queued row, loads a plain processing configuration,
downloads its images into `TEMP_ROOT/jobs/<job_id>/images`, and spawns a child
that processes only those local paths. The API requests cancellation in
the database; only the owning worker slot terminates its child. Completed
output is stored in `new_files` until the user downloads it.

Before starting the thread pool, the worker refreshes Pokémon data under
`TEMP_ROOT/Pokemons`. `pokemon.csv` and `Pokemons/images/` are the processing
source; job children must not scrape Pokémon pages. Refreshes compare the live
list with valid cached rows and download only missing entries.

Setting deletion is asynchronous. A deletion request blocks edits, copies, and
new runs. The worker waits until all related queued/running jobs are terminal,
then deletes the setting; completed jobs retain their output and their setting
reference becomes null. `setting_image_deletion` durably queues S3 keys for
removal after the database commit, including retries after storage failures.

One worker replica is supported. On startup it returns interrupted `running`
jobs to `queued`.

## Database rules

Flyway SQL is the schema authority and the current clean state is V1. There is
no migration path from the legacy Flask SQLite database. Runtime deployments
must use PostgreSQL.

For every schema change:

1. Keep matching schema changes in V1 under PostgreSQL and SQLite locations.
2. Apply each dialect to a fresh/test database.
3. Run `./migrations/generate_models.sh`.
4. Review the generated model diff and run tests.

The SQLite schema exists solely for generating SQLAlchemy models. It must not
influence application queries or database behavior. Write application queries
for PostgreSQL, using PostgreSQL-specific SQL and SQLAlchemy dialect features
where appropriate; do not add SQLite compatibility branches or workarounds.
Run database-backed application tests against PostgreSQL by setting
`TEXT_EVOLVER_TEST_POSTGRES_URL`; tests requiring a database skip if it is unset.
Do not use SQLAlchemy
metadata creation or restore Alembic/Flask-Migrate.

Schema string columns use `TEXT`. Preserve user-facing size limits in service
validation rather than database `VARCHAR` declarations; editable setting text
fields currently accept at most 64 characters, except source matchers (unit,
phrase/regex, image trigger), which accept at most 128. Settings contain at most
100 elements across all rule types and at most 512 MiB of images, including
retained files and new uploads while excluding replaced files.

## Configuration and paths

Configuration is defined in `src/text_evolver/config.py` and loaded from
environment variables. `DATABASE_URL`, `SECRET_KEY`, `S3_ENDPOINT_URL`,
`S3_BUCKET`, `S3_ACCESS_KEY`, and `S3_SECRET_KEY` are required. Root `.env` is
for the app/Compose; `migrations/.env` is intentionally separate for manual
Flyway execution. Both real files are ignored; update their example files when
variables change.

Use `pathlib.Path`. Runtime paths must be environment-provided or relative to
the current project/container working directory. Never add host-specific or
Windows absolute paths, string-built separators, or CWD temporary files.

## Web and security conventions

- Use one assignment target per statement throughout Python source and tests.
  Avoid chained assignments and tuple/list unpacking assignments. Store a
  multi-value function result once, then assign each needed value separately.
- Keep the server-rendered UI unless a separate API/frontend change is
  explicitly requested.
- All state-changing forms require the signed-cookie CSRF token.
- Keep failed password-login attempt throttling in `web/login_throttle.py`.
  Do not apply general request-rate limits to account, reauthentication,
  recovery, Google, or WebAuthn endpoints.
- `CSRFMiddleware` validates HTTP POST requests centrally; do not duplicate
  CSRF validation in route handlers.
- Account IDs and all account foreign keys use UUIDv4 identity. Use the account
  UUID's 16 bytes as the WebAuthn user handle; do not add a separate handle.
- Session cookies contain opaque IDs; `browser_session.token_hash` is the primary
  key. Keep the original CSRF mechanism in a separate signed cookie containing
  only `csrf_token`. Authentication cookies expose only the opaque token;
  never put identity metadata, flash messages, or flow payloads in cookie sessions.
  Use dedicated flash/flow records. Session references cascade on hash rotation.
  Sessions expire exactly seven days after sign-in with no idle extension.
  Reauthentication is fresh for five minutes and preserves the session deadline.
- Password recovery requires an enrolled WebAuthn credential and successful
  verification; Google and email do not authorize forgotten-password resets.
- Passwords are stored only as Argon2id hashes in `user_password`. Never log
  plaintext credentials or password hashes.
- Localization defaults to browser headers. Only account settings expose a
  language selector: default (null preference), en, or ru. Do not use anonymous
  language cookies or controls on login/registration.
- Parse submitted booleans explicitly; never use `eval()`.
- Validate setting ownership/public access in services or route dependencies.
- Sanitize upload names with `Path(filename).name` and preserve job isolation.

## Processing notes

Text matching operates on a punctuation-cleaned copy and splices replacements
back into original words to preserve punctuation and capitalization. Preserve
the behavior of `text_cleaner`, `find_in_clean`, `text2int`, and
`replace_iteration` when refactoring.

`ProcessUnit` owns transformation rules only. Document adapters retain the
last native text part and containing block. The processor transforms combined
block text so replacements can cross DOCX runs or markup text nodes, then maps
the result back to native parts to retain inline formatting. Empty-block and
image checks run once per paragraph/tag. Create a new `ProcessUnit` and adapter
for every input document so counters and image-separation state do not leak
between files.

Image captioning uses Pillow and must remain headless. Selenium is used only by
the worker-start Pokémon cache refresh. Driver construction goes through
`processing/browser.py`, uses no custom user profile, and must always close the
driver. Keep cache refresh network behavior mockable in tests.
